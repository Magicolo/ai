## Non-Obvious Facts (read before touching anything)

### 1. Host vs Container Boundary
- **opencode runs on host only, comfy MUST stay in container** via `serve.sh` (`docker compose run --build --rm --detach ...`). Never `comfy launch` on host; host has no comfy binaries by design (`pip uninstall comfy-cli/comfy-mcp`, `~/.config/comfy-cli` removed, project-local `.opencode/opencode.json` carries `mcp: { comfy-mcp: { type: remote, url: http://localhost:9000/mcp, oauth:false }}` — moved out of global `~/.config/opencode/opencode.json` 2026-09-10, so the server is scoped to this folder).
- `serve.sh` uses **`run` not `up`** intentionally — keep it that way. `run --service-ports` publishes 8188/7860/9000 under the fixed container name `comfy` (`--name comfy`, stable and resolvable on the compose network). `docker ps` shows `comfy Up (healthy)`. A second `serve.sh` while one runs fails fast on the name — same outcome as the old port-bind failure, clearer message.
- zoomy lifecycle is driven by `zoomy.sh`: it starts zoomy itself (`run --build --rm --detach --service-ports --no-deps`, ephemeral `comfy-zoomy-run-<hash>`, UI at `http://localhost:7861`). Standalone since 2026-09-16: the image carries the whole engine (diffusers/ACE/MMAudio/RIFE), models live in the `zoomy_models` volume, outputs land in `./Zoomy/output` — no comfy involvement, no `depends_on`, no `ZOOMY_COMFY_ADDRESS`. First launch ever needs the one-shot provisioner (command in `zoomy.sh`). Never restart comfy or edit `serve.sh` for zoomy — `comfy` is an untouched backup.
- `COMFY_BIN` / `COMFYUI_URL` env passthrough is via `mcp-proxy` style `--pass-environment` (now inlined bridge). Don't set them manually.

### 2. Dockerfile Rebuild Safety
- Rebuilds are frequent (`--build` on every `serve.sh`). Workflows MUST survive rebuild.
- ALL requirements are baked from the **host checkout** at build time (2026-09-21 rewrite, fixes the `comfy-aimdo` crash): first line `# syntax=docker/dockerfile:1`, then `COPY --parents Comfy/requirements.txt Comfy/custom_nodes/*/requirements*.txt /opt/comfy-requirements/` + a `RUN` loop `pip install --no-cache-dir --requirement` per file over `/opt/comfy-requirements/...` AND `/comfy/custom_nodes/*/requirements*.txt` (the image-cloned QoL packs). The loop covers core + every custom node on the host; per-file install keeps pip resolution isolated.
- **Lesson (do not regress)**: the old pattern fetched `--requirement https://raw.githubusercontent.com/.../master/requirements.txt`; Docker cached that layer, upstream added `comfy-aimdo==0.5.5` (used by main.py/comfy/storage.py), and `serve.sh` died with `ModuleNotFoundError: No module named 'comfy_aimdo.storage'`. Host-path COPY means the layer hash tracks the local checkout, so a `--build` always picks up a moved ComfyUI commit. **Never re-introduce remote requirement URLs in the Dockerfile.**
- `COPY --parents` needs the `# syntax=docker/dockerfile:1` directive (stable frontend; `1.7` stable fails, `1.7-labs` works — `:1` is used) and is required because a plain wildcard `COPY */requirements.txt` silently collapses same-named files to one. No-match wildcards are silently ignored, so zero custom nodes is safe.
- The four QoL packs are still `git clone`d into `/comfy/custom_nodes/...` at build (fresh-clone fallback for the volume overlay); their requirements are installed by the loop, not by the clone RUN. Never add host-side `pip install` — installs belong in the image.

### 3. Entry.sh Dual-Process & Patches
- PID1 is `init` (docker `init: true` handles zombie reaping); entry.sh `wait -n` then kills the other pid for clean `docker stop`.
- Must run `comfy set-default /comfy` every boot because config at `/root/.config/comfy-cli/config.ini` is not volume-persisted.
- **Loopback fixed key patch**: upstream `nodes.py:_resolve_workflow_key` hashes workflow JSON, so `comfy run` (cli) vs UI Queue produce different workflow hashes → different cache dirs → history lost. We patch to return fixed `"ernie_zoom_fixed"` when `cache_path` is `/comfy/output/loopback_ernie_zoom` (or legacy `"ernie_zoom"`). Patch is idempotent and applied at runtime via `entry.sh` Python heredoc + at build via host file. If you clone loopback fresh, entry.sh re-patches.
- **Square edges**: entry.sh stamps `Comfy/user/default/comfy.settings.json` to `{"Comfy.LinkRenderMode":"Straight"}` (options: Hidden/Linear/Spline/Straight — Straight = square right angles). Also creates file if missing. Workflows carry `_linkRenderMode:Straight` in `extra` as documentation, but real setting is global.
- **Cache migration**: on boot, if `/comfy/temp/image_loopback/ernie_zoom_fixed` exists and new `/comfy/output/loopback_ernie_zoom/ernie_zoom_fixed` does not, `cp -a` migrates. Manual migration already done for current history (4 frames).
- **No runtime pip installs anymore** (2026-09-21): the old `for req in /comfy/custom_nodes/*/requirements.txt` boot loop is gone — dependencies are baked into the image (§2). Nodes added after a build are handled by ComfyUI-Manager at startup.

### 4. Loopback Confinement to `output/`
- Old `cache_path="ernie_zoom"` → `_cache_dir` returned `/comfy/temp/image_loopback/<workflow_key>/ernie_zoom` (relative path, trapped under `get_temp_directory()`). Escaping with `../../output` is blocked by `candidate.startswith(base_root)`.
- New `cache_path="/comfy/output/loopback_ernie_zoom"` → `_cache_dir` returns `/comfy/output/loopback_ernie_zoom/<workflow_key>` (absolute branch, `os.path.isabs`). With fixed key, final dir is `/comfy/output/loopback_ernie_zoom/ernie_zoom_fixed/` containing `history/`, `cached_img.png`, etc. **All generation is now under `Comfy/output/`** — cleanup is `rm -rf Comfy/output/*` (also clears history).
- Workflow widgets: `Image-Loopback-Load/Cache/Configure` all have `cache_path` widget 0 = new absolute path. Prettier formatting preserves this.

## Known Gotchas
- Host `comfy` binary absent by design — use `docker exec <cid> comfy ...` instead.
- Changing `cache_path` to an absolute under `/comfy/output` is the ONLY way to confine loopback; relative paths are jailed under temp.
- Workflow `id` changes on save can drift hash key — fixed key patch prevents history loss.
- Frames are **1376×768** (official Ernie preset; ~20s/frame on 4060 Ti). Don't change resolution without re-checking VRAM + re-rendering the seed PNG at the new size (cold-start seed must match frame size). Line-art loop is **512×512** (~3.5s/frame; its seed must stay 512² too). Glow loop is **512×512**: live file = FLUX.2 Klein 9B KV fp8 (`~3.5s/frame`, seed `klein_glow_seed.png`), Flux.1 twin `glow_drawing_flux1_zoom_loop.json` (`~13s/frame`, seed `glow_draw_zoom_seed.png`) — both need 512² seeds; denoise 0.45 (Klein) / 0.40 (twin) + fixed seed for temporal consistency; rotation node 304 bypassed by default — un-bypass for the 0.5°/frame inward spiral; 312 ColorTransfer + 313 AdjustContrast 1.05 lock the palette to the newest saved frame (fallback seed) and hold the black floor — do NOT bypass 313 or the color drift returns; 315 LoadLatestFrame auto-resumes from the newest frame, so clear the frames dir to restart from the seed.
- Panorama loop is **768×512** (~2.5s/frame on Klein 9B; seed `line_art_pano_seed.png`): each Queue pans right by `Pan step` px/frame via ImagePadForOutpaint + DifferentialDiffusion and composites the kept pixels bit-exact (ImageCompositeMasked, mask = pad mask) — do NOT replace the composite with a plain VAEEncode→VAEDecode round-trip or frames soften cumulatively; 315 LoadLatestFrame auto-resumes, so clear the frames dir to restart from the seed.
- Stretch loop is **768×512** on Z-Image Turbo bf16 (seed `line_art_stretch_seed.png`): each Queue stretches the frame with its anchor half a width past the right border (333 EmptyImage canvas of width W+step, 334 paste frame at 0,0, 335/336 copy the frame's rightmost step px into the right pad so it carries CONTENT — a black pad compounds a growing void — 337 AdjustBrightness 0.8 (user-tuned; lower = darker/sparser) dims before generation, then 83 crop x = 1.5×step, width W−step, then 84 rescale 768×512) → every column stretches, most at the left (~12 px/frame) and least at the right (~4 px/frame), material streams left; CN group 301/302/303 is ENABLED by default (bypass it to disable the structure lock; the Turbo CN pairs with the Turbo base); denoise 0.8; prompt = sparse windswept white-line-art landscape with clearly visible muted accents (organic motifs: snowy mountains, plants/structures growing out of and burrowing into the ground, spiral towers, searing cracks, shining stars, floating birds, small hopping animals, wind spirals, figurative trees); the video tail was moved to the dedicated `video_export.json` (drop the sequence folder in its dropdown, then Queue — it loads the frames, upscales 2× with RealESRGAN_x4plus_anime_6B.pth + Lanczos 0.5, interpolates 4× FILM and writes h264 crf 15 at 1536×1024); 315 LoadLatestFrame auto-resumes, so clear the frames dir to restart from the seed (a sequence made before the void fix cannot heal — clear it to restart).
- Long video exports are chunked: `video_export.json` node 10 `VHS_BatchManager` (`frames_per_batch`, default 32) streams the sequence through upscale + interpolation + encode so RAM stays bounded (an all-at-once pass OOMs the container on long folders — `ImageUpscaleWithModel` materializes the full 4× tensor per batch and `FrameInterpolate` the whole interpolated batch); cost = one skipped interpolation pair (a tiny hitch) per chunk boundary.
- `AdjustBrightness` (core node) declares no `step` in its INPUT_TYPES, so the browser widget rounds its factor to 0.1 (e.g. 0.85 → 0.9); the user chose to leave it as is (2026-09-21) — don't "fix" it without asking (it would need an entry.sh-reapplied patch or a local node pack).
- `Comfy.LinkRenderMode` must be `Straight`; if edges look curved, re-check `comfy.settings.json`.
- zoomy finalize: the `-audio.mp4` twin (not the same-named mp4) carries the soundtrack — preview/ship the twin. Audio floor is `max(interp/32, 1.0)` because ACE-Step rejects anything below 1.0 s. Long sequences finalize segmented (48-frame windows, per-stem FLAC stems + Python ffmpeg assembly — full design in `Zoomy/DESIGN.md` §8): a single-pass finalize OOMs MMAudio past ~200 frames, so NEVER "simplify" back to one pass. Never use `acrossfade` for segment joins (collapses on short tails — manual fades/delays instead); every assembly step verifies non-empty outputs. The segmented path is unit-tested, not run live — only single-window finalize is verified live.
- zoomy e2e writes real artifacts under `Zoomy/output/` (`<sequence>/frame_*` + `<sequence>_*`, flat since 2026-09-16 — no `Zoomy/` nesting, no `Zoomy_` prefix) — clean test renders from inside the zoomy container after verification (`rm -f /output/cold_* /output/ab2_* /output/*.flac` + stray sequence frames); never delete the user's `Ernie_Zoom_*`/`Z_Zoom_*` files by pattern accident. Same for the line-art loop: `LineArt_Zoom_*` are its own artifacts (frames + ffv1 mkv + VHS metadata png).
- zoomy interrupts land via the engine's `threading.Event` (checked between stages) plus the loop-stop flag — no Comfy `/interrupt` or history polling anymore. An e2e A/B with empty `lora_selections` does NOT deactivate a loaded adapter (`set_adapters` is skipped) — use a fresh engine/sequence for clean comparisons.
