# 021 — SHA-256 helper exists 5× with different chunk sizes and names

- Status: open
- Severity: major (correctness-adjacent duplication; chunk size/error behavior
  already drifted)
- Area: structure — hashing utility
- Rank rationale: five identical "chunked hash" loops; the fix is one tiny
  import-safe module.

## Technical description

```
$ rg -n "def _?sha256" Voyage/voyage -g '*.py'     # verified live 2026-09-25
Voyage/voyage/model_registry.py:219:def _sha256(path: Path) -> str:
Voyage/voyage/workers/video_ltxv.py:158:def sha256_file(path: Path) -> str:
Voyage/voyage/supervisor.py:77:def sha256_file(path: Path) -> str:
Voyage/voyage/workers/video_causvid.py:243:def sha256_file(path: Path) -> str:
Voyage/voyage/workers/video_causvid.py:252:def sha256_text(text: str) -> str:
Voyage/voyage/media.py:211:def _sha256_file(path: Path) -> str:
```

Naming (`_sha256` vs `sha256_file` vs `_sha256_file`) and chunk sizes (8 MiB vs
64 KiB) already drifted. Workers can't import supervisor/media (image-boundary
concern is real) but nothing prevents one tiny import-safe module.

## Why this is an issue

Five identical chunked-hash loops with drifted names and chunk sizes (8 MiB
versus 64 KiB) mean every hashing improvement — short-circuiting, error
handling, larger chunks — must be applied five times or the copies diverge
further, and error behavior already has. The fix is a single small stdlib-only
module that worker images can import safely, so the cost of unification is
trivial against the permanent fivefold tax. Until it lands, the
hash-short-circuit work that finalize performance (018) depends on cannot be
done once and trusted everywhere. The next person to touch hashing pays five
times over.
